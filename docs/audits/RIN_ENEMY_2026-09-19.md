## What changed

- The animated enemy is the engine's Rin character (real human proportions, armour, hair) with the MotionMatching Gem's Jog1 /
  Walk2 mocap clips, instead of the `STW_CHARACTER_01` cube figure. The cube figure stays the default profile.
- `SkeletalCharacterProfile` (actor, idle / locomotion / death clip, origin offset, probe joint, material prefix) makes the
  presentation class character-agnostic. `Box()` holds the previous hard-coded values and is pinned by unit tests; the refactor
  alone was gate-verified with an identical acceptance marker set (`player-slice-20260919T150636Z`).
- `Rin.fbx` references external textures (`Mocap\Rigs\Rin\Textures\*.tif`) that ship neither with the gem nor with this repo, so
  every material imported untextured and rendered white. 17 original constant-colour PBR materials
  (`tools/assets/generate_stw_rin_materials.py`, deterministic, no external assets) replace them. The imported model does not
  reference source materials by name, so the presentation entity gets an Atom `MaterialComponent` and each slot is mapped
  to its override at runtime (34 of 35 slots; `CHARACTER_MATERIAL_SLOT` / `_OVERRIDES` in `Game.log`).

## Not done / open

1. **Idle and death reuse Walk**: the engine library has neither. A proper idle clip and a real ragdoll (still only a state machine)
   are open product requirements.
2. **Enemies beyond the first still render as the static Rin mesh** (untextured white, bind pose) because only index 0 goes
   through the skeletal presentation; they need the same profile and materials.
3. The first-person weapon is still an untextured block without arms; textures are constant-colour, not authored skin detail.
4. Rin is an engine sample stand-in (Apache-2.0 / MIT), not final STW character art.
